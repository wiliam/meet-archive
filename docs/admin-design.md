# Summit Archive Admin — дизайн

Дата: 2026-07-03

## Контекст

Summit AI Notes работает в триальном режиме; старые встречи выносятся скриптом
`summit/archive_summit_meetings.py` в архивную SQLite-базу
`summit-archive/database.sqlite` (+ папки `<uuid>/` с аудио и `document.md`).
Нужна простая веб-админка над архивом: браузинг встреч, папки, теги, участники,
транскрипты, полнотекстовый поиск, экспорт транскрипта в `.md`. Сначала локально,
позже — на хостинг.

## Решение

**Read-only** веб-приложение на **Python 3 + FastAPI + Jinja2** (серверный рендеринг,
без JS-фреймворков). База открывается в режиме `mode=ro` через URI — админка
физически не может повредить архив. Python выбран, потому что весь существующий
тулинг проекта (скрипт переноса) уже на Python.

### Структура

```
summit-archive-admin/
├── app.py            # FastAPI: маршруты, опциональный Basic Auth
├── db.py             # все SQL-запросы (единственная точка доступа к базе)
├── export.py         # генерация markdown из данных встречи
├── templates/        # base.html, index.html, meeting.html
├── static/style.css
├── requirements.txt  # fastapi, uvicorn, jinja2
├── README.md         # запуск локально + заметки про хостинг
└── tests/            # test_db.py, test_export.py (pytest, фикстурная mini-БД)
```

Путь к архиву задаётся переменной окружения `SUMMIT_ARCHIVE_ROOT`
(по умолчанию `../summit-archive` относительно app.py).

### Страницы и маршруты

- `GET /` — список встреч: заголовок, дата, длительность, папка, теги, число
  участников. Сайдбар: папки (с количеством встреч) и теги. Фильтры
  `?folder=`, `?tag=`, поиск `?q=`.
- Поиск `q` идёт по FTS5-таблицам `documents_fts` (title/notes),
  `transcription_fts` и `topics_fts`; результаты объединяются по `document_id`,
  для совпадений в транскрипте показывается `snippet()`.
- `GET /meetings/{id}` — карточка встречи: метаданные (дата, длительность, папка,
  теги, язык), участники (`document_speakers` → `speakers`), темы (`topics`),
  action items, транскрипт (`transcription_segments` ORDER BY `start_time`,
  спикер + таймкод + бейдж источника mic/system).
- `GET /meetings/{id}/export.md` — download сгенерированного markdown
  (метаданные + темы + action items + транскрипт). Браузер сохраняет на диск.
- `GET /meetings/{id}/files/{name}` — отдача файлов встречи с диска
  (`document.md`, `microphone.m4a`, `system.m4a`) по whitelist имён;
  аудио проигрывается тегом `<audio>` на странице встречи, если файл есть.

### Данные

- Активные встречи: `documents.deleted_at IS NULL` (конвенция приложения).
- Даты — Unix epoch (DOUBLE) → форматируются в шаблонах.
- FTS-таблицы автономные, но в архиве заполнены и поддерживаются триггерами
  (проверено: 39/10590/172 строк) — используем напрямую.
- Пустой заголовок FTS-запроса / спецсимволы экранируются (запрос оборачивается
  в кавычки-фразы по словам, чтобы избежать синтаксических ошибок MATCH).

### Хостинг (позже)

- Приложение stateless: контейнер/VPS + файл базы и папки встреч рядом
  (volume). Обновление архива = загрузка свежего `database.sqlite`.
- Опциональный HTTP Basic Auth: включается переменными `ADMIN_USER`/`ADMIN_PASSWORD`
  (личный контент встреч не должен висеть открытым). Локально — выключен.

### Ошибки

- Нет базы по пути — понятное сообщение при старте.
- Несуществующий id встречи — 404.
- Отсутствующие файлы на диске (аудио/md) — элементы UI просто не показываются.

### Тестирование

- pytest: фикстура создаёт временную SQLite с той же схемой ключевых таблиц
  и парой встреч; тесты на запросы (`list_meetings` с фильтрами/поиском,
  `get_meeting`, транскрипт) и на генерацию markdown.
- Ручная проверка: запуск `uvicorn`, прогулка по страницам, экспорт md.

## Вне скоупа (YAGNI)

- Редактирование данных, аутентификация сложнее Basic Auth, статистика,
  просмотр chat_sessions, векторный поиск по chunks.
